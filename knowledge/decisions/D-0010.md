# D-0010 — Grip is optional profile data, independent of combat class

**Decision:** `WeaponProfile.grip` is an `Optional<Grip>` with `one_handed`
and `two_handed` wire names. `Grip` compiles against the JDK alone. The profile's
existing synchronized data map carries it. Absence preserves a consumer's prior
hold; misspellings fail the codec. Native capability precedence is unchanged,
including for presentation. The old constructor descriptor stays available for
already compiled providers and leaves grip absent.

**Why:** Rusty asked for the gun providers and Armed Pillagers to share grip/stance
data. A pistol's combat class is not a reliable declaration of its hands, and a
client-registration-time grouping cannot respond to a datapack reload. Grip is
an item fact; live aim/reload belongs to the holder/stack, not to this profile.

**Rejected:** inferring grip from weapon class; changing old profiles' pose by
default; a second presentation lookup that bypasses the resolved native provider.

**Verification:** the old codec lost declared grip and accepted its misspelling;
both regression tests failed before the change. `WeaponCodecsTest` covers the wire
contract and legacy default; `PrecedenceGameTests` covers conflicting native/data
grips, declined capability, and an undeclared legacy profile on a real server.
